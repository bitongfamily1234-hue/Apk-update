# APK and IFF analysis

Store extracted APK components and loader/decryption investigation notes here. Avoid committing large APK binaries or private signing material.

## Texture investigation tools

- [iff_texture_resolver.py](iff_texture_resolver.py): diagnostic resolver/exporter for a known VCTEXTURE descriptor offset.
- [iff_texture_inventory.py](iff_texture_inventory.py): 16-byte-aligned candidate scanner, JSON inventory, PNG previews for confirmed linear formats, contact sheets, and optional raw payload dumps.
- [native_texture_format_survey.md](native_texture_format_survey.md): ARM64 native format sizing/conversion findings, including confidence boundaries.
- [iff_resource_inventory.md](iff_resource_inventory.md): current scan totals and non-texture resource leads.
- [texture_pointer_recovery.md](texture_pointer_recovery.md): paired file-entry pointer validation and exact reference matches.

The inventory script's accepted records are candidates filtered by structure and bounds, not guaranteed-live textures. Use descriptor/hash/entry metadata and reference images to validate each candidate. The resolver and inventory utilities do not modify source IFFs.

## Mobile IFF runtime integration

The original compiled Chaquopy engine modules are shipped inside `assets/chaquopy/app.imy`. The mobile-only correction is now implemented and tested against those actual Python 3.11 modules:

- [mobile_iff_patch.py](mobile_iff_patch.py): guarded correction for paired type-2 pixel bases and native formats 5/6.
- [patch_app_imy.py](patch_app_imy.py): preserves the original core code object, wraps its initialization, injects the patch module, verifies all other archive members byte-for-byte, and refreshes the app.imy hash in build.json.
- [smoke_test_patched_app.py](smoke_test_patched_app.py): opens, previews, replaces, saves, and reopens a synthetic mobile IFF using the actual app engine.
- [mobile_iff_patch_report.md](mobile_iff_patch_report.md): implementation, validation results, and rebuild limitations.

The original encrypted `.py.enc` assets, DEX files, and integrity/certificate checks are not modified. The original legacy IFF path remains active for files which do not validate as NBA 2K20 Mobile VCTEXTURE layouts.

## Current build status

<badge>Runtime patch passed</badge> The GitHub Actions workflow [Build and smoke-test mobile IFF patch](../.github/workflows/mobile-iff-patch.yml) passed the unit suite, built a patched Chaquopy `app.imy`, then tested it with the app's actual compiled engine modules.

The tested patch package is a Chaquopy integration artifact, **not yet a rebuilt/installable APK**. This repository does not currently contain the complete Android Gradle project or an authorized signing configuration. Kotlin/Dex and Python certificate-integrity checks are deliberately left unchanged. A proper APK rebuild must use the original Android project and its authorized signing setup, with the certificate allow-list regenerated by the normal build process.

## Non-texture resources (side investigation)

The IFF resource inventory records type-1 entries, opaque headers and offsets as leads. No scene/model/OBJ extractor is claimed yet because their resource serialization has not been verified. Keep this as a secondary track until the texture patch is integrated into a rebuilt application.
